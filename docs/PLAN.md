# 执行计划书 · PLAN

> 把任务书拆成 Agent 能一口吃掉的小块。
> 粒度铁律：**一个任务要能在一次会话内完成并验证**。做不完说明还能再拆。

## 0. 拆分原则

1. 单个任务改动文件尽量 ≤ 5 个
2. 每个任务必须有明确的验收命令或验证步骤
3. 依赖关系写成 DAG，不允许循环依赖
4. 先搭骨架后填肉：数据模型 → 核心逻辑 → 接口 → 界面 → 打磨
5. 每个任务都要能独立验证，不要把验证全压到最后

## 4. 单任务执行循环

Agent 每接一个任务，固定走这五步：

```
1. 领任务  → 从 BOARD.md 认领，切分支 feat/T-XXX-简述
2. 读约束  → 重读 AGENTS.md 第 7 节红线 + 本任务的验收方式
3. 做      → 小步改，每步可运行
4. 验      → 跑验收方式，逐条记录结果（不许口头声称完成）
5. 收      → 提交、推分支、更新 BOARD.md 状态
```

任一步失败超过 3 次 → 停止，写阻塞记录，不硬扛。

## 5. 状态定义

| 状态 | 含义 |
|---|---|
| 待办 | 还没开始 |
| 进行中 | 已被认领，正在做（同时只允许一个任务处于此状态） |
| 待审 | 自测通过，等待人工 review |
| 完成 | 已合入且验收通过 |
| 阻塞 | 卡住，必须写明原因与已尝试的方案 |

## 一、为什么有第二域

`RAG项目_准备清单.md` 的"方案 A"原计划把**自有项目文档**（保洁系统：需求/库表/接口/部署/状态机）入库，
但用户**否决了那个方向**，改为在 `作业` 文件夹里另选语料，并要求**新增第二语料域**而不是替换现有语料。

**为什么不能替换或追加**（详见 `PLAN.md §2.16`）：`eval/README.md §3.5` 规定**题目定稿后不得修改**，
"改题等于换评测集、历史得分不可比"；而现有 20 题的 `gold_sources` 全部指向第一域语料。
替换 ⇒ E-01~E-08 全部实验与所有历史数字失去可比性；追加 ⇒ 同题不同语料、数字立刻不可比。
**新增第二域可以两样都保住**，而且**不需要改 `SPEC.md`、不需要改 `src/`** ——
`RAW_DIR` / `CHROMA_DIR` / `CHUNKS_FILE` / `COLLECTION` 都是可配置项（`src/config.py:41,46,49,51`）。

## 四、已知限制

1. **Word 转换会丢结构**：表格被压成线性文本、图片被丢弃、目录页的页码仍留在正文里
   （如 `01_…` 开头有"目录 1 引言 1 1.1 编写目的 1 …"）。**这些噪声是真实存在的**，本域不额外清洗 ——
   若后续做"语料清洗"对照实验，这正是**天然的 before 状态**。
2. **`.pdf` 两份是案例材料**，82 页与 101 页，含少量图片与表格；`pypdf` 只抽文字，图表内容丢失。
3. **本域语料不入公开仓库**（见 `.gitignore`）：内容是本人课程作业（**含学号、同学与导师姓名**）与课程/案例材料，
   属隐私与第三方版权范畴。⇒ **clone 本仓库后无法直接跑 `doc_qa_se`**，需要用户自己放语料；
   这与第一域的处理一致（第一域也只放行 `00_*.md` 一份自有文档）。
4. **中文总量 169,083 字是"抽取到的中文正文字符数"**，不是词数；两份 PDF 的字数由 `pypdf` 实测（29,115 + 15,653）。
5. **切块 830 块**（≈204 字/块，低于 `CHUNK_SIZE=400`）：因为 `src/chunking.py` 把 **markdown 标题当硬边界**，
   而 Word 转出的文本标题密集、短段多。**这是预期行为**，但会让本域的平均块长明显短于第一域（400 块 / 106,829 字 ≈ 267 字/块）。
